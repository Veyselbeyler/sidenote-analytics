How to see GA4 data for a single page

Updated October 24, 2026 · 5 min read

In short: Use Pages and screens for views and engagement time, the Landing page report for sessions and traffic sources, and a free-form exploration for anything else. Users and sessions are not page metrics in the strict sense, so they never add up across pages.

To see GA4 data for a single page, open Reports > Engagement > Pages and screens and filter the table to that page's path, for example /pricing. You will get its views, active users, engagement time and key events for the selected date range. For sessions and traffic sources, use the Landing page report or a free-form exploration instead, because those numbers depend on how visitors arrived, not only on what they viewed.

This guide walks through all three options, explains which metrics belong to a page and which do not, and shows a quicker way to check a page while you are looking at it.

Option 1: the Pages and screens report

This is the fastest route, and it works in every GA4 property without any setup.

  1. In GA4, go to Reports, open Engagement and select Pages and screens.
  2. Check that the first column shows Page path and screen class. If it shows page titles, use the dropdown above the column to switch. Paths are more reliable, because several pages can share a title.
  3. Type the path into the search box above the table, such as /pricing. The search matches any path that contains the text, so /pricing also returns /pricing/teams.
  4. Set the date range in the top right. Turn on Compare in the date picker to see the previous period next to the current one.

The row for your page shows Views, Active users, Views per active user, Average engagement time per active user, Event count and Key events. For an exact match rather than a "contains" search, use Add filter at the top of the report and choose the exactly matches condition.

This report does not include sessions or traffic sources by default. That is intentional, and the next section explains why.

Why some metrics don't belong to a page

Every GA4 metric has a scope. Knowing the scope tells you whether a number can be read for one page on its own.

  • Event-scoped metrics, such as views and event count, are recorded on the page itself. They add up neatly: the views of all pages equal the site's total views.
  • Session-scoped metrics, such as sessions and engagement rate, describe a whole visit. A visit that touches five pages counts once for each of those pages, so page sessions never add up to the site total.
  • User-scoped metrics, such as users and new users, describe people. One person who reads three pages is a user of each page.

Here is a simple example. A visitor lands on your blog, then opens /pricing and /signup. In GA4 that is one session and one user for the site, but /pricing and /signup each report one session and one user too. Nothing is wrong with the data. The visit simply belongs to every page it included.

So when you look at sessions for a single page, ask which question you are answering. Is it "how many visits included this page?" or "how many visits started here?" GA4 has a different place for each.

Option 2: the Landing page report

If you want to know how many visits started on a page and where those visitors came from, use Reports > Engagement > Landing page. Each session is counted once, on the first page of the visit, so these numbers do add up across pages.

The report shows Sessions, Active users, New users, Average engagement time per session and Key events. To see traffic sources for one landing page:

  1. Search for the page path in the table.
  2. Click the + next to the column heading to add a secondary dimension.
  3. Choose Session default channel group for channels, or Session source / medium for more detail.

This is the right report for SEO work. Filter the channel to Organic Search and you can see how many search visits each page earns, and what those visitors did next.

If the Landing page report is not in your navigation, someone may have customized the report menu for your property. An administrator can add it back from the Library at the bottom of the Reports menu.

Option 3: a free-form exploration

Explorations let you combine any dimensions and metrics, which is useful when the standard reports don't show what you need.

  1. Go to Explore and start a Free form exploration.
  2. Under Dimensions, import Page path and screen class and Session default channel group.
  3. Under Metrics, import Views, Sessions, Engagement rate and Key events.
  4. Drag the page dimension to Rows and the channel to Columns, then add the metrics to Values.
  5. Add a filter: Page path and screen class exactly matches /pricing.

Sessions here means "sessions that included this page", for the reasons described above. Explorations can also be sampled on very large date ranges, and both reports and explorations can hide small numbers behind data thresholds when Google signals is turned on. If a figure looks different from the standard report, check the indicator at the top of the exploration first.

The shortcut: check the page while you're on it

All three options start in GA4 and end with a filter. If you check pages often, for example while reviewing content or after publishing a change, switching tabs and re-typing paths adds up.

SideNote Analytics is a free Chrome extension that does the filtering for you. Open any page of your site, click the icon, and the side panel shows that page's GA4 numbers, compared with the previous period. It reads the same GA4 Data API as your reports, with read-only access, and no data leaves your browser.

Common questions

Why does my page have more views than users?

One person can view a page several times, in the same visit or on different days. Views count each view, while users count each person once for the date range. The ratio is shown as Views per active user.

Why don't the page numbers add up to the site total?

Views and event counts do add up. Users and sessions don't, because one visit or one person can include many pages. Use the Landing page report when you need session counts that add up.

How do I include query parameters, such as UTM tags?

Page path and screen class leaves out the query string. Use Page path + query string in the Landing page report, or Page location in an exploration, to see the full URL.

Can I see data for a page from today?

Standard reports usually update within a few hours, and some figures can change for up to two days while GA4 finishes processing. For a live view of the last 30 minutes, use the Realtime report.
