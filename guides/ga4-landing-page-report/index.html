Using the GA4 landing page report

Updated November 9, 2026 · 5 min read

In short: Open Reports > Engagement > Landing page to see where sessions start. Each session is counted once, on its first page, so it is the right report for comparing pages as entry points. Add Session default channel group as a secondary dimension to see which pages earn organic search visits.

The GA4 landing page report shows the first page of every session, along with how many sessions started there, how many users arrived, and what those visits produced. You find it under Reports > Engagement > Landing page. Because each session is counted once, on its first page, it is the most reliable place in GA4 to compare pages as entry points, for example for organic search, campaigns or referrals.

This guide explains what the report counts, how to break it down by traffic source, how to connect it with Search Console data, and what the (not set) row means.

What the report shows

The report's main dimension is Landing page: the page path and query string of the first page view in a session. If a visitor arrives on /pricing?ref=newsletter, that is the row their session is counted in.

The default metrics are:

  • Sessions: visits that started on the page.
  • Active users and New users: people behind those visits.
  • Average engagement time per session: how long those visits lasted while the site was in focus.
  • Key events and Total revenue: what the visits produced.

Everything in the report is session-scoped. A key event that happens three pages later is still credited to the page where the visit began. That is exactly what you want when the question is "which pages bring in visits that go somewhere?"

Why sessions add up here, and nowhere else

In most page reports, one visit can be counted on several rows, because it included several pages. In the landing page report, every session has exactly one first page, so the session counts across all rows add up to the site total.

That makes the report the right choice for questions such as:

  • How many visits did this page bring in last month?
  • Which pages are the main entry points from search?
  • Did a redesign change how many visits start on a page, or only how many pass through it?

For a fuller explanation of how scope affects page metrics, see How to see GA4 data for a single page.

Breaking it down by traffic source

The report becomes much more useful with a secondary dimension:

  1. Open Reports > Engagement > Landing page.
  2. Click the + next to the Landing page column heading.
  3. Choose Traffic source and then Session default channel group, or Session source / medium for more detail.

Each landing page now appears once per channel. To focus on search, type Organic Search into the search box above the table, or use Add filter at the top of the report to keep only that channel. You now have a list of the pages that earn organic visits, with the engagement and key events those visits produced.

A practical example: a blog post brings in 1,200 organic sessions a month with 30 key events, while a product page brings in 300 organic sessions with 45 key events. The blog post is the bigger entry point, but the product page converts its search traffic far better. Both observations are useful, and only the landing page report shows them side by side.

Adding engagement rate

The report does not include engagement rate by default. An Editor or Administrator can add it with Customize report (the pencil icon), then Metrics and Add metric. For entry pages, it is the most honest version of the metric, because each session is judged once, on the page where it started. GA4 engagement rate, explained covers why the same metric can be misleading in other page reports.

Combining it with Search Console

If your GA4 property is linked to Search Console, GA4 also offers a Google organic search traffic report. It uses the same landing page dimension and adds Search Console metrics: clicks, impressions, click-through rate and average position, next to GA4 metrics such as engaged sessions and key events.

The report is part of the Search Console collection, which is not published by default. To see it, open the Library at the bottom of the Reports menu, publish the Search Console collection, and then go to Reports > Search Console > Google organic search traffic. Search Console data appears with a delay of about two days.

Expect clicks in this report and organic sessions in the landing page report to differ. They are measured by different systems, and GA4 only records visits from people whose browsers load the tag, which depends on consent settings and ad blockers.

What "(not set)" means

A (not set) row appears when a session has no page view event. This can happen when a session times out and the visitor interacts with the page again without loading a new one, or when events are sent without a page view, for example from a server. A small (not set) share is normal. A large or growing one is worth checking with whoever maintains your tagging.

Query strings and duplicate rows

Because the dimension includes the query string, one page can appear as several rows: /pricing, /pricing?ref=newsletter, /pricing?utm_source=linkedin and so on. When you want one number per page, search for the path without parameters and add up the rows, or build a free-form exploration with Landing page and a filter that matches the beginning of the path.

Checking a landing page while you are on it

SideNote Analytics shows the sessions, users, organic search share and key events of the page you are viewing in Chrome's side panel, compared with the previous period. It is a quick way to see whether a page's traffic has moved before you open the full report.

Common questions

Where did the old "Landing page" report from Universal Analytics go?

GA4 has its own Landing page report under Engagement. If it is missing from your menu, an Editor or Administrator can add it back to the navigation from the Library.

Can I see landing pages for a single campaign?

Yes. Add Session campaign as a secondary dimension, or filter the report by it. UTM-tagged links make this much easier.

Why is my home page the top landing page for "Direct" traffic?

Direct includes typed URLs and bookmarks, which usually point to the home page, and visits whose source could not be identified, such as links opened from some apps. Treat large Direct numbers with care.
